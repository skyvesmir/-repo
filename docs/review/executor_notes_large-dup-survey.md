## スキルの不明点・矛盾・実現困難だった点

1. **インベントリ TSV の作り方が現実的でない。**
   - §3-2 と references §6 は「TSV に書き出して find_candidates.py に渡す」としている。
   - しかし、コネクタの応答は会話に直接入るだけで、ファイルに落とす手段がない。今回は 1,096 行を手で写した（出力量が大きく、写し間違いの危険もある）。
   - 対策として、圧縮形式と展開スクリプトを使い、行数・ID 長・重複で検算した。
   - スキルに、必要な列だけを写す、ID は候補だけ後から引く、などの指針があるとよい。
2. **除外フォルダの扱いとフォルダ一覧の順序。**
   - §0-3 は「除外フォルダは中身を列挙しない」としている。
   - 私は最初に `mimeType = folder` の全体検索を 2 ページ取り、その中で `node_modules/pkg-XX` の名前が見えてしまった。
   - 除外判定（package.json の有無）は、直下のファイル一覧を見ないとできないため、順序が矛盾しがち。
   - 以後は親 ID 指定の幅優先に切り替えた。フォルダの全体検索は使わず、まず root の子から降りるよう明記するとよい。
3. **ユーザーの「約 1,500 件」と実測 1,096 件の差の扱いが書かれていない。**
   - 差は除外した `tool-app` 配下（推測）としたが、件数は未確認と明記した。
   - 除外フォルダの件数だけ数える方法（本文なしの件数取得）は、コネクタにないため難しい。
4. **Phase 5 のテンプレート（整理案）と、ユーザーの依頼（重複の一覧のみ）の粒度が合わない。**
   - 重複（D）、版違い・要確認（Q）、低確度、重複でないもの、次のアクションだけに絞った。
   - 命名の問題（L: spec_final、最新版など）は、改名（R）の表を出さず、重複の表の文脈でだけ触れた。
   - Vault の規約把握（§5-2）と Frontmatter 提案（F）は、Obsidian 最適化の依頼がないため省いた。
   - 「依頼が重複調査だけのときにどこまで出すか」を書いてあると迷わない。
5. **§4-2（最新版の判定）に当てはまらないケース。**
   - 企画書は、最終版2 が最終版に「追記あり」を足した形で、最新版は追記がなく更新日時だけ新しい。
   - 見出しのラベルだけが違う場合に「相手の内容をすべて含む」かどうかが定義されていない。
   - 保守的に「分岐の可能性・要確認」とし、ゴミ箱は提案しなかった。
6. **ネイティブ形式（Google ドキュメント）の重複検出が手作業になる。**
   - スクリプトはネイティブ形式を S・Z から外すため、名前違いの同一ドキュメント（議事録_0612 と 2025-06-12_定例）は検出されなかった。
   - 名前に含まれる日付（0612 と 06-12）と作成・更新の近さから、人が気づいて確認した。
   - 名前違いのネイティブ文書の候補抽出ルールがあるとよい（例: 名前中の日付が同じ、更新日が近い、など）。
   - サイズ（1,276 B が同じ）は、スキルの指示どおり根拠にせず、手がかりにとどめた。
7. **「スニペットで足りるか」の基準が曖昧。**
   - §3-3 の「先頭部分」は確度「中」相当だが、小さい Markdown は、スニペットの文字数が fileSize と一致すれば全文と言える。
   - md（69 B、77 B、96 B）はこの根拠で全文と扱った。PDF・docx・xlsx・Docs は `read_file_content` で全文を読んだ。
   - 今回のモックでは、スニペットと全文は同一だった。
8. **本文確認の件数の数え方（§3-3 の 30 件）。**
   - 全文読み取り 13 件と、スニペットのみ 17 件（Vault の md 4 件、同名 Docs 13 件）を合算して約 30 件とした。
   - 同名 Docs のサンプル確認を「本文確認」に含めるかは、スキルに規定がない。
9. **§6-1（ログ・整理案の新規作成は承認不要）とユーザーの「まだ何もしないで」の関係。**
   - 安全側に倒し、Drive には何も作成せず、保存の申し出だけにした。
10. **モックデータの時刻の不整合。**
    - 未整理の一部ファイルは `createdTime`・`modifiedTime` が現在（2026-09-29）より未来だった（例: 2026-12-26）。
    - 更新日時は補助情報とする方針に従い、判断には使っていない。
11. **画像の扱い。**
    - D7（IMG_0166.jpg）と Q3（icon.png と banner.png）は、§3-3 のとおり「中」以下にとどめ、`read_file_content` は使っていない。
    - 「画像を実際に見比べて確認」をユーザーへの依頼として書いた。
