## Skill の指示のうち、わかりにくい・矛盾・実行しにくい・従わなかった点

1. **obsidian.md を読む順序**: SKILL.md は「Obsidian 対象の Markdown があるとき、Phase 4 の前に読む」と言うが、私は新規ノート 2 件（イェレナ、第04章）を前回の規約メモ（状態ブロックの conventions）だけで判定し、ログを保存した後に obsidian.md を読んだ。読んだ後に結論が変わる点はなかった（Vault 外の「最新版」名は対象外、空ノートは要確認、リンク先確認など）。ただし手順としては逸脱。定期実行の差分調査で「規約メモが状態ブロックにあり、新規ノートが規約どおりに見えるだけ」の場合に obsidian.md を読む必要があるのかは、SKILL に書かれていない（読み込みコストの割に得るものが少ない）
2. **obsidian.md §2「Frontmatter の規約を BRIEF で集計」**: 定期実行の差分調査では実施しなかった（状態ブロックの conventions を再利用）。SKILL の scheduled.md はこれを明示していない。新規ノートの Frontmatter が規約に合うかは新規 2 件の先頭だけで判断した
3. **差分の調査を広げない**と「範囲の判定のために親をたどる」の兼ね合い: 状態ブロックにはサブフォルダ（人物、章、原稿など）の ID がないため、親をたどる代わりに創作 / Vault ルート / 未整理の子を OR で 1 回取得した。結果として差分外のファイル（企画書 2 件、定例会議 2 件など）のメタデータまで見えてしまい、「差分の外で気づいた問題は報告するが、調査は広げない」との線引きが曖昧になった。状態ブロックにサブフォルダの ID と名前の対応表を持たせるか、`get_file_metadata` で親だけをたどる方法を明記すると迷わない。私は差分外の観察を、確度 低・未調査として報告に書くにとどめた（IDを付けた提案にはしていない）
4. **差分外の既存問題の扱い（キャラ_カルタ.md）**: 人物規約から外れた改名候補だが、差分の外で、被リンク検索（obsidian.md §7-1）もしていない。第04章.md が今回リンクしているので優先度は上がるが、SKILL に従って R 項目にはせず観察として書いた。「新規ノートが既存の規約違反ノートにリンクした」場合に R を出してよいかは書かれていない
5. **状態ブロックの version 1 → 2**: 前回は version 1 で `log_folder` / `trashed_in_search` / `reviewed` を欠いていた。移行の手順は書かれていないので、欠けた欄を追加して version 2 にし、`reviewed` は空にした（履歴を推測しない）。前回までに検討済みだった組があっても再検討されうる
6. **状態ブロックの位置**: templates.md は「ログの先頭に置く」と言うが、前回のログは見出し行の後に置いていた。前回と同じく見出しの直後に置いた（読み出しには支障がない）。「先頭」が見出しの前かどうか曖昧
7. **§4-3 分岐の判定**: 最新版が最終版2 の第一章を「言い換え＋加筆」しているとき、文言レベルでは相手にない内容を互いに持つ（分岐）が、意味的には改稿に見える。SKILL は文言と意味のどちらで包含を判定するか明記していない。私は文言で判断し、分岐＝要確認を維持した（意味では分類 3 の可能性が高いと書いた）
