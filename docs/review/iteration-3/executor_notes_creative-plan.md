## わかりにくい・矛盾している・使えない・従わなかった点
1. **§6-1（obsidian.md）の被リンク検索と、確認済みの定義**: obsidian.md §6-1 は改名候補ごとに `fullText contains` 検索を 1 回ずつ行うと書き、§6-2 は「関係するノートの本文を読んだ」ものを「確認済み」とする。今回は Vault の Markdown 15 件すべてを BRIEF で本文全体（1000 文字未満、`...` なし）として読み済みだったので、検索は省略して「確認済み」とした。BRIEF が全文とみなせる条件は SKILL.md §Phase 3 にあるが、「確認済み」との対応は明示されていない。読み済みの場合に検索を省略してよいかを明記してほしい。
2. **obsidian.md §2 の規約把握は「フォルダごとに 1 回、pageSize 10」**: 実際は 15 件を 1 回の検索（6 フォルダの OR、pageSize 30）で取った。SKILL.md Phase 1 の「OR でまとめる」に合わせたが、obsidian.md の文言とは異なる。
3. **D の ID が二重の意味を持つ**: templates.md は D=重複としているが、§6-1 では「D は承認が要るゴミ箱」として扱われる。分類 3・4（残す前提）の行にも D を振ったので、「全部と返信されたら D 以外を実行」の解釈が曖昧になる。整理案の冒頭で「ゴミ箱の承認が要るのは D1〜D3」と明記して対処した。分類 3/4 は D にしない、または別記号にする方が安全。
4. **§4-4 の共有ルールと §4-1 の推奨アクションの噛み合わせ**: 正本の優先順（① 置き場所、② リンク・共有、③ 名前、④ 作成日時）と、「ゴミ箱側が共有されていれば正本を入れ替える」ルールがあるが、入れ替えた結果ゴミ箱側になる方（名前が整い、作成も古い）にも共有確認が要るのかは、文言上あいまい（「ゴミ箱側の 1 件だけ」と書かれている）。入れ替え後の側を追加で確認した（1 呼び出し）。また、共有されている正本の改名（R7）で共有先に名前の変更が見えることへの指示はないため、注意を自分で足した。
5. **§4-3（分岐）と §4-1 分類 3 の境界**: 未整理/シューニャ.md は、相手にない内容（年齢 16 歳）と、包含されない値の変更があるので、厳密には「分岐 → 要確認」にも読める。更新日時の順（旧稿が古い）、内容量、Vault の作成日より前の日付から、分類 3 とし、年齢の食い違いを別途 Q5 に立てた。「値が変わった場合は包含とみなすか」が明記されていない。
6. **ネイティブ形式の完全一致（議事録の組）**: §2 Phase 3 で BRIEF 全文とみなせれば本文比較になるとあるので、確度「高」とした。Google ドキュメントのコメントや版履歴（`includeComments` 引数がある）を比べるべきかは SKILL に書かれていない。比較していない旨を「検出の限界」に書いた。
7. **画像（IMG_0001.jpg）の移動**: 内容を見られず、写真フォルダへ移す規則もない。§7-1 の「移動は中以上」に届かないと判断して Q4 にした。§4-5 は重複判定用の規則で、単独の画像の分類は対象外に見える。
8. **範囲外フォルダの扱い**: §0-3 は移動先の候補として子を一覧するだけとある。議事録・写真の子を一覧したところ、写真に重複らしき名前（`IMG_1003 (1).jpg`）が見えた。調査はせず、1 行で範囲外として言及した。言及してよいかは SKILL に明記がない。
9. **Vault 外の Markdown 名（未整理/シューニャ.md の `_v01`）**: Vault 内のシューニャ.md と同名のため、同じ場所（Vault）に入れると衝突する。Vault 外なので被リンクへの影響はないとして、リンク確認は「対象外」とした。テンプレートの「リンク確認」列の選択肢（確認済み／検索ベース／未確認）に「対象外」がないため、追加した。
10. **ツールで実行できない項目**: Vault のローカルアクセスがないので F1〜F3 はパッチ提示のみ。R1・R2 は「Obsidian で改名」（コネクタでは実行しない）。そのため「R は全部」と返信されても、Claude が Drive で実行できるのは R3〜R7 だけになる。返信のしかたで区別した。
